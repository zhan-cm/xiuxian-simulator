# 《问道长生》V2 沉浸式修仙界面开发蓝图

## 1. 文档目的

V1.0 已完成原始规则文案的可运行复现，并建立稳定的 Python 规则引擎、FastAPI 本地接口、JSON 存档、React 界面与自动测试。本阶段不重写这些基础能力，而是将表现层从“三栏信息面板”升级为场景优先的 2D 单机修仙 RPG。

目标体验介于剧情修仙 RPG 与世界沙盒修仙 RPG 之间：玩家首先看到当前地点、人物和事件，再按需要进入地图、坊市、宗门、背包等独立系统页面。自由输入继续保留，但不再承担所有日常操作。

## 2. 北极星体验

玩家进入游戏后应当产生以下感受：

1. 我正身处一个明确的修仙地点，而不是阅读一组数据卡片。
2. 当前最重要的事件、人物与抉择能在三秒内被看懂。
3. 气血、灵力、修为、时间等状态随时可见，但不会争夺主要注意力。
4. 地图、坊市、宗门、人物、背包拥有各自的空间结构和操作语言。
5. 绝大多数常规行为可以点击完成，自由输入用于表达预设按钮之外的行动。
6. 所有规则仍由本地引擎结算，视觉升级不会牺牲数值连续性或旧档兼容。

## 3. 明确不做的事情

- 不改造成实时 3D 游戏。
- 不在本阶段重写为 Unity、Unreal 或 Godot。
- 不引入实时寻路、殖民模拟或多人联机。
- 不用通用后台组件库替代现有国风设计。
- 不删除 V1.0 的规则、存档迁移、便携卷宗和成果巡览。
- 不直接模仿其他游戏的具体素材、布局或受保护美术。

## 4. 产品与技术边界

### 4.1 保留

- Python 规则引擎与所有数值结算；
- FastAPI 本地接口；
- JSON 存档及历史版本迁移；
- React、TypeScript、Tailwind CSS、Radix、Motion、TanStack Query、Zustand；
- 34 页成果巡览和隐私安全验收摘要；
- 可选 OpenAI 叙事润色。

### 4.2 新增

- 沉浸式游戏外壳 `ImmersiveGameShell`；
- 场景舞台 `SceneStage`；
- 轻量角色状态 `CultivatorHud`；
- 地点、时间与世界状态 `WorldHud`；
- 底部场景导航 `WorldNavigation`；
- 独立系统页容器 `SystemSurface`；
- 美术资产清单、预加载与降级策略；
- 音乐、环境声与操作音效管理层；
- 必要时为地图或战斗局部引入 Canvas/PixiJS，默认继续使用 DOM、CSS 与 SVG。

## 5. 信息架构

### 5.1 常驻场景页

- 顶部：角色头像、境界、三项核心状态、当前地点、回合与历法。
- 中部：当前地点背景、人物站位、事件氛围与世界变化。
- 下部：事件标题、短叙事、明确抉择与自由行动。
- 底栏：洞府、地图、坊市、人物、宗门、行囊、更多。

### 5.2 独立系统页

| 页面 | 核心布局 | 首轮目标 |
|---|---|---|
| 九州地图 | 卷轴地图、地点标记、路线详情 | 五域与当前地点可视化 |
| 坊市 | 商人区域、分类货架、物品详情 | 买卖路径不再依赖文字列表 |
| 人物 | 立绘画廊、档案、关系与互动 | 六位核心 NPC 可浏览 |
| 宗门 | 山门、身份、任务、藏经阁、势力 | 弟子到掌门路径清楚 |
| 行囊 | 装备位、物品格、筛选和详情 | 使用、装备和数量一眼可见 |
| 功法 | 主辅修槽、术法、熟练度、悟道 | 修炼流派形成组合感 |
| 战斗 | 敌我舞台、五行资源、技能与状态 | 每回合行为和后果清楚 |
| 突破 | 路线、资源、风险、心魔与雷劫 | 形成独立仪式感 |

## 6. 视觉方向

首选“淡彩水墨 + 青绿山水 + 少量鎏金”的桌面端 16:9 设计：

- 背景承担地点氛围，信息面板使用半透明宣纸与深色墨层；
- 重要抉择使用玉牌或卷轴，不使用通用网页卡片；
- 主色为松烟墨、青玉绿、宣纸白，金色仅用于重要信息；
- 危险、受伤和禁用使用低饱和朱砂红，不使用高亮霓虹色；
- 正文保持现代中文可读性，书法字体仅用于标题、印章和少量装饰；
- 动效以雾、呼吸、纸卷、灵气和轻微视差为主，支持减少动效设置。

## 7. 美术与声音资产规划

### 7.1 第一轮资产

- 8 至 12 张地点背景；
- 六位核心 NPC 半身立绘及三种基础情绪；
- 玩家男女基础剪影或立绘；
- 40 至 60 个常用物品、技能和状态图标；
- 灵气、受伤、获得物品、突破与雷劫基础特效；
- 3 至 5 首循环背景音乐与 15 至 25 个操作音效。

### 7.2 质量与授权

- 原型资产可以生成或自制，最终资产必须记录来源、授权与修改方式；
- 不直接下载或临摹其他游戏素材；
- 图片优先使用 WebP，透明立绘保留高质量 WebP/PNG；
- 音乐使用 OGG/MP3 双格式时应明确浏览器回退顺序；
- 所有资源缺失时必须有纯 CSS/SVG 降级表现，不能阻止游戏启动。

## 8. 分阶段交付

### 阶段一：场景外壳与视觉样板（38% → 48%）

- 完成本开发蓝图；
- 建立独立重构分支；
- 实现场景背景层、轻量 HUD、地点氛围与底部导航；
- 保留全部旧功能入口和成果巡览；
- 以洞府主界面作为第一张北极星页面；
- 建立至少一个组件测试，确保导航与场景信息可访问。

验收：首次进入时视觉重心位于场景与事件，不再是左右栏；在没有任何新图片资源时也能完整运行。

### 阶段二：主游玩流程（48% → 62%）

- 创角、洞府、事件、对话、抉择和自由行动迁入新外壳；
- 事件正文默认精简，完整结算按需展开；
- 重要 NPC 支持立绘站位与情绪状态；
- 快捷行动根据情境变化。

验收：从开始游戏到完成一次探索、一次关系互动和一次存档，全程无需返回旧三栏布局。

### 阶段三：地图、坊市与人物（62% → 75%）

- 卷轴式五域地图；
- 坊市商人、货架和物品详情；
- 人物画廊、档案和众生缘网；
- 地点与人物的新事件角标。

验收：地图、购物、送礼和人物交互均可点击完成，禁用原因明确。

### 阶段四：宗门、洞府、行囊与成长（75% → 86%）

- 宗门、藏经阁、任务和势力页；
- 洞府设施与灵田场景热点；
- 行囊、装备、功法、法术、悟道、灵兽和阵法独立页面；
- 长列表使用局部滚动，页面标题始终保留。

验收：所有成果巡览页面均有明确归属，旧功能入口无遗漏。

### 阶段五：战斗与突破（86% → 94%）

- 敌我对峙舞台；
- 五行、灵力、技能、状态与回合反馈；
- 战斗动效、胜负与战利品结算；
- 人道、地道、天道突破仪式；
- 心魔与雷劫演出。

验收：战斗信息无需阅读完整日志即可理解，全部数值仍由现有规则引擎产生。

### 阶段六：美术、声音与商业化打磨（94% → 99%）

- 批量接入场景、人物、物品与特效资产；
- 音乐、环境声、操作音效与音量设置；
- 页面转场、加载、空状态和错误状态统一；
- 资源预加载、压缩和低性能降级；
- 完成第三方许可与美术资产清单。

验收：连续游玩一小时无明显重复噪音、突兀切换、图片闪烁或资源阻塞。

### 阶段七：玩家验收与交付（99% → 100%）

- 迁移并检查全部成果巡览页面；
- 桌面与窄屏核心流程验收；
- 旧档、便携卷宗、启动器与干净解压目录回归；
- 自动测试、构建、性能与隐私检查；
- 根据玩家反馈完成最后修正。

验收：满足正式发布检查清单后，才允许合并并准备下一次完整 Release。

## 9. 测试策略

- Python 全量回归必须持续通过；
- React 组件测试覆盖 HUD、导航、抉择、场景降级与主要系统页；
- 每阶段重新构建生产资源并运行发布包冒烟测试；
- 成果巡览继续使用隔离快照，不写入真实存档；
- 对 `prefers-reduced-motion`、键盘焦点、窄屏和资源加载失败建立回归用例；
- 玩家存档不得出现在 Git、测试快照或发布包中。

## 10. Git 与发布策略

- V1.0 正式版及 `v1.0.0` 标签保持不变；
- V2 开发在 `codex/immersive-ui` 分支推进；
- 阶段成果提交并同步 GitHub，但不创建零散标签或 Release；
- 在沉浸式界面完成玩家验收前不覆盖稳定版 `main`；
- 最终是否合并、版本名称及 Release 时间由用户明确决定。

## 11. 当前状态

- V1.0 既定复现范围：100%；
- V2 沉浸式修仙 RPG 新目标起点：约 38%；
- 当前执行：阶段一“场景外壳与视觉样板”。
