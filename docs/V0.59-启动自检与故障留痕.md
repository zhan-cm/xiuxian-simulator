# V0.59 启动自检与故障留痕

V0.59 是正式玩家验收前的启动可靠性收口。它不增加新的玩法入口，而是让“检查通过”真正代表新版界面具备运行条件，并在失败时留下足够清楚、可以安全分享的报告。

## 深度环境检查

`main.py --check` 现在同时核对：

- Python 3.11 或更高版本；
- FastAPI 与 Uvicorn 本地接口依赖及其版本；
- 原始 DOCX 规则文档与结构化抉择内容；
- 兼容网页的 HTML、CSS 和 JavaScript；
- React 生产入口引用的全部本地资源与第三方许可清单；
- `data/saves` 的真实创建、写入、原子替换、回读和清理能力。

存档探针只使用随机命名的短暂内部文件，检查结束即清除，不读取、修改或覆盖玩家卷宗。

## Windows 启动闭环

- `检查环境.bat` 会把屏幕所见结果同步保存到 `data/logs/最近一次环境检查.txt`；
- `启动新版界面.bat` 在依赖安装和必要的前端构建完成后执行同一套检查；
- 任何检查失败都会保留黑色窗口、显示具体项目并给出报告位置；
- 已存在但损坏或低于 Python 3.11 的 `.venv` 会被明确识别，并提示玩家重命名后让启动器重建，不会在旧环境上反复安装失败；
- 检查通过后才启动本地服务，避免浏览器打开后才发现资源残缺；
- `data/logs` 被 Git 忽略，也不会进入正式发行包。

## 隐私边界

报告只包含组件名称、通过/失败状态、Python 与接口依赖版本、相对资源名和非敏感错误类型。它不记录：

- 玩家姓名、角色状态、经历或存档正文；
- `.env`、OpenAI API 密钥、模型请求内容；
- Windows 用户名或游戏目录的绝对路径。

V0.59 仍是 `main` 上的内部稳定版本，不创建标签或 Release。玩家视角验收通过后再统一发布唯一的 `v1.0.0`。
