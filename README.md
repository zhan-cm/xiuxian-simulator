# 修仙模拟器 · 问道长生 V0.29 成果巡览与全页验收版

这是一个本地可运行的基线项目。目标是先忠实保留《修仙模拟器 · 问道长生.docx》的规则与世界观，做出可启动、可创角、可推进回合、可修炼、可存读档的最小版本，再通过试玩逐步补全大模型叙事、数值引擎和网页界面。

## 当前实现

- Python 标准库即可运行，不依赖 Node、数据库或第三方包。
- 启动时直接读取 `docs/修仙模拟器 · 问道长生.docx`，原文是 V0.1 的权威规则源。
- 支持两面结构化创角：基础信息/出身/道途，以及灵根/体质/六维/天赋。
- 严格校验年龄 16~60、六维单项 1~15 且合计 60、天赋点正好使用 5 点。
- 出身、体质和天赋会真实修改角色属性；支持 `面板`、`修炼`、自由行动、`存档`、`读档`、`帮助`。
- 独立数值引擎严格计算资质、灵根、功法、灵气、心境、体质和闭关倍率。
- 支持 `闭关3月`、`闭关2年`、小境界突破、失败退回 70% 修为和寿元坐化。
- 随机判定由存档内种子驱动，同一存档可复现、可测试。
- 大境界支持人道、地道、天道三种路线，并真实消耗不同突破资源。
- 心魔劫与雷劫分别判定；失败会重伤、跌境、留下暗伤、走火入魔或陨落。
- 破境成功后获得三项随机“逆天改命”，由玩家亲自选择其一。
- 东洲探索会真实推进时间，可获得灵药、妖兽材料、灵石和三道破境材料，也可能受伤或陨落。
- 坊市支持按原文参考物价买卖，包含 500 灵石的筑基丹，交易会真实写入乾坤袋与存档。
- 可参加青云宗、丹霞谷或玄剑门入门试炼，并完成采药、巡逻、猎妖、护送、镇守任务赚取灵石与贡献。
- 战前敌情面板会严格提示境界差距；高一境伤害压制为 40%，高两境以上仅剩 5%。
- 支持攻击、施法、防御、观察、两轮蓄势绝技、服丹与遁走，命中、暴击和五行克制均独立判定。
- 生死战可能重伤或陨落，切磋只分胜负；战利品必须由玩家亲自选择是否拾取。
- 支持黄、玄、地、天阶功法与法术参悟；失败会按原文规则损毁残卷。
- 可配置一门主修、两门辅修、一项当前法术，以及武器和护甲；主修品级直接影响修炼速度。
- 功法、法术和法宝已接入命中、五行、攻击、防御、遁速及灵力消耗结算。
- 支持炼丹、炼器和制符；配方真实消耗材料，失败会炸炉或毁料，成功次数会提升技艺等级。
- 洞府可升级静室、丹房、器坊、灵田、聚灵阵和禁制，设施会影响闭关、制作或灵气浓度。
- 灵田支持种植、跨月生长与收获；火球符和神行符已经接入战斗与逃命结算。
- 内置原文六位核心 NPC，记录年龄、身份、境界、所在地、喜好与独立好感。
- 支持交谈、送礼和论道；礼物偏好与论道判定会真实影响关系和角色成长。
- 好感达到要求后可由玩家主动结为道侣，不受双方性别限制；道侣可双修并同时增长修为与好感。
- 多段暧昧或道侣关系会累积尘缘波澜，并在人物牵绊卡中显示冲突强度。
- 达到条件后可主动面对情劫，在坦诚相告、暂避锋芒与一心问道之间作出不可替代的选择。
- 坦诚相告的结果由存档随机种子稳定判定；情劫结局、好感变化和旧缘都会写入存档。
- 支持通灵秘境、上古洞府、心魔幻境与虚空裂缝，并按境界严格拦截致命区域。
- 秘境采用入口确认与三阶段推进；每阶段可谨慎探索、强行探索或带着已有收获退出。

- 普通自由行动接入 20% 可复现奇遇，包括赠丹、灵雨、残碑、袭村、传音与心魔等事件。
- 每个月都有一位核心 NPC 自主闭关、游历、办事、斗法或拜访故交，不再只等待玩家互动。
- NPC 的所在地、伤势、道行积累和最近动态写入存档，并通过 `世情` 面板持续展示。
- 好感达到相识后，NPC 可能主动发出论道、同行或委托邀约；玩家可在期限内接受或婉拒。
- 除道侣外，可主动确立纯友谊、结义、师徒或宿敌路线，各自带有明确好感与境界门槛。
- 宗门职位扩展为外门、内门、真传、长老和掌门；每次晋升同时校验贡献、境界并进行试炼判定。

- 叛宗采用二次确认，并真实清空贡献、扣除声望、增加业力与叛宗追杀标记。

- 玩家所属宗门参战时可驰援前线、固守山门或闭关不出；选择会影响战局、贡献、声望与伤势。

- `天下` 面板可查看下一届大会时间、世界局势值与最近大事记，跨年闭关也不会漏掉事件。

- 修为、气血、灵石、资源、好感和时间变化通过前后状态对比自动生成，不依赖容易出错的文字匹配。
- 战斗、破境、情缘、秘境、坊市、宗门和危险事件拥有各自的视觉主题，全部组件均为项目内原生制作。

- 新增 `检查环境.bat` 与 `main.py --check`，启动前会检查 Python、规则文档、结构化内容、网页资源和存档目录。
- Windows 启动器会优先使用项目虚拟环境，也能回退到系统 Python，不再因缺少 `.venv` 直接无法运行。

- `Narrator` 接口把叙事与游戏状态分开，后续可以接任意大模型 API，而不必改存档格式。

## 剧本、规则与存档放在哪里

当前版本没有使用数据库，这是有意的架构选择：

- 原始剧本文案保存在 `docs/修仙模拟器 · 问道长生.docx`，作为不可随意改写的权威来源。
- 可由策划调整的静态交互内容放在 `data/content/*.json`，随 Git 和版本发布。
- 数值公式、状态机和判定逻辑放在 `src/xiuxian_simulator/`，由自动测试保护。
- 每局动态状态保存在 `data/saves/*.json`，只留在玩家电脑，不提交 GitHub。

单机本地游戏目前没有并发写入，也没有需要数据库处理的大量查询，JSON 更容易查看、备份、迁移和修复。等未来出现数百名动态 NPC、跨存档世界或模组索引时，再将动态世界数据迁移到内置 SQLite；静态剧本仍保留为版本可读的 JSON。

## 环境

- Windows 10/11

- Node.js 暂不需要

## 首次启动

最简单的方式是直接双击项目中的：

```text
启动网页版.bat
```

浏览器会自动打开 `http://127.0.0.1:8765/`。关闭启动窗口即可停止服务。

若启动失败，先双击 `检查环境.bat`。所有项目显示“通过”后再启动游戏。

也可以继续使用命令行版本：

在 PowerShell 中执行：

```powershell
cd E:\Projects\xiuxian-simulator
.\.venv\Scripts\python.exe main.py
```

进入游戏后输入：

```text
开始游戏
确认默认创角
修炼
存档
```

退出可输入 `退出`、`quit` 或按 `Ctrl+C`。

## 可选：启用 OpenAI 叙事

复制 `.env.example` 为 `.env`，然后填写：

```text
XIU_NARRATOR=openai
OPENAI_API_KEY=你的密钥
XIU_MODEL=gpt-5.4
```

密钥只保存在本机 `.env`，不要提交到 GitHub。若不需要云端叙事，保持 `XIU_NARRATOR=local` 即可。

cd E:\Projects\xiuxian-simulator

- 进一步降低完整推演记录的视觉权重，并让桌面右侧三块辅助面板以相同高度轨道排列。

## V0.29 成果巡览与全页验收

- 顶部新增“成果巡览”入口，使用与正式游戏完全相同的组件展示 14 个主要页面状态。
- 巡览依次覆盖：初始入世、角色创建、洞府主界面、探索地图、坊市交易、宗门事务、人物情缘、战斗抉择、秘境探索、突破路线、天下局势、道途终章、洞天卷宗和游玩指引。
- 右下角巡览控制器提供上一页、下一页、直接跳转、页码进度和逐页检查重点；方向键可以翻页，Esc 可以退出。
- 巡览数据只存在于当前页面内，不调用行动接口、不触发规则结算，也不会覆盖自动存档；退出时会恢复进入巡览前的真实游戏状态。
- 桌面端采用悬浮验收控制器，手机端改为紧凑底部面板，确保仍能查看主要界面。

### 成果巡览使用流程

1. 双击“启动网页版.bat”，进入游戏页面。
2. 点击右上角“成果巡览”。
3. 按“下一页”依次检查 14 个页面，也可以通过下拉列表直接跳转。
4. 根据控制器中的“本页检查重点”核对布局、信息和按钮状态。
5. 最后一页点击“完成巡览”，或随时点击“退出”；原来的游戏进度会原样恢复。
